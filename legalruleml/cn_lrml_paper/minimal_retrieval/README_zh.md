# 最小检索实验：民法法条检索 + CLeXML 语义网

这个文件夹是论文表 2（民法法条检索）三行结果的**最小可运行版本**：一个脚本、一个数据目录，只依赖 `numpy` 和 Python 标准库，运行不到 1 秒，数字与论文完全一致。

```sh
python minimal_retrieval.py                 # 跑完整实验
python minimal_retrieval.py --explain 529   # 逐步展示第 529 题
python minimal_retrieval.py --explain 669   # 逐步展示第 669 题（两个金标）
```

## 实验一步步怎么做

### 第 1 步：读语义网，变成“条文 → 条文”的有向边

`read_graph()` 直接解析 LegalRuleML：

1. `LegalSource` 的 `sameAs` 是 Akoma Ntoso 地址，如 `…/civil-code/zho@/!main#art_1245`，由此知道它是第 1245 条。
2. `Association` 把规则绑定到法源，由此知道规则 `c1245-…` 来自第 1245 条。
3. 规则之间的关系换算成条文之间的边，**每条边都有类型和方向**，意思是“检索到条文 b 时，应该去看条文 a”：

| 类型 | 来源 | 方向含义 | 边数 |
|---|---|---|---|
| `override_up` | 标准 `lrml:Override(over, under)` | 被覆盖的一般规则 → 优先的特别规则 | 143 |
| `override_down` | 同上 | 特别规则 → 它排除的一般规则 | 143 |
| `depends` | 依赖候选（规则 r 的条件谓词由 r′ 推出） | r → r′（去看前提） | 2,499 |
| `exception` | 例外候选（r 的“除非”谓词由 r′ 推出） | r → r′（去看例外） | 242 |
| `textref` | 明文引致（“依照本法第 X 条”） | 本条 → 第 X 条 | 51 |

### 第 2 步：第一阶段 Dense 检索

查询向量和每条法条向量做点积。向量已经归一化，点积就是余弦相似度。按相似度排序，取前 20 条为**候选**，前 5 条为**种子**。

### 第 3 步：第二阶段，在同一批 20 个候选里重排

```
S(a) = ŝ_dense(a) + w_e · ŝ_要件(a) + Σ_t w_t · N_t(a)
N_t(a) = Σ_{种子 b，且语义网有 b →t a} ŝ_dense(b)     （再在候选内 min-max 归一化到 [0,1]）
```

- `ŝ` 表示在 20 个候选内 min-max 归一化后的分数。
- 证据只沿边的方向，从种子推给候选。
- 候选之外的条文不动，排在后面，所以 Recall 的上限不变，只改变排序。

### 第 4 步：在开发集上选权重

只用 76 道开发题，以 NDCG@10 为目标：先选要件权重 `w_e`，再对每种关系类型轮流选权重（候选值 0, .05, .1, .2, .3，两轮，并列时取较小的）。结果是 `w_e=0.05`、`depends=0.1`、`override_down=0.05`，其余为 0。测试集只用来报告结果。

### 第 5 步：在测试集上算 Recall@10 和 NDCG@10

## NDCG@K 是怎么算的

相关性是二值的：金标条文 rel = 1，其他条文 rel = 0。

```
DCG@K  = Σ_{i=1..K} rel_i / log2(i + 1)                  i 是名次（从 1 开始）
IDCG@K = 把 min(|G|, K) 个金标都排在最前面时的 DCG          G 是金标条文集合
NDCG@K = DCG@K / IDCG@K                                   取值 0~1，1 表示金标全部排在最前面
```

各名次的折扣 `1/log2(i+1)`：第 1 名 1.000，第 2 名 0.631，第 3 名 0.500，第 4 名 0.431，第 5 名 0.387 …… 第 10 名 0.289。名次越靠后，命中得分越少；排在前 10 名之外则不得分。

最后对 176 道测试题的 NDCG@10 取平均，就是表里的 0.4027。

### 例 1：第 529 题（1 个金标），语义网把金标从第 2 名推到第 1 名

题目：狗在被张某偷的过程中咬伤张某。金标是**第 1245 条**（饲养动物致害的一般规则，含“被侵权人故意或重大过失”的但书）。

**Dense 排序**：第 1246 条第 1 名，第 1245 条第 2 名。

```
DCG@10  = 1/log2(2+1) = 0.6309        金标在第 2 名
IDCG@10 = 1/log2(1+1) = 1.0000        只有 1 个金标，最理想是排第 1
NDCG@10 = 0.6309 / 1.0000 = 0.6309
```

**语义网的作用**：种子里的第 1246 条（未采取安全措施）和第 1247 条（烈性犬）都是特别规则，在 LegalRuleML 中各有一条 `Override` 覆盖第 1245 条的一般规则。沿 `override_down`（特别规则 → 被排除的一般规则）方向，它们把证据推给第 1245 条：

```
N(1245) = ŝ(1246) + ŝ(1247) = 1.00 + 0.65 → 归一化后 1.00；乘权重 0.05，加分 +0.050
S(1245) = 0.986（dense）+ 0.045（要件）+ 0.050（语义网）= 1.081   → 第 1 名
S(1246) = 1.000 + 0.042 + 0.020 = 1.062                           → 第 2 名
```

```
重排后 DCG@10 = 1/log2(1+1) = 1.0000，NDCG@10 = 1.0000
```

### 例 2：第 669 题（2 个金标），以及这种做法的局限

题目：外卖员跳江救人，用力过猛把对方手臂拉骨折。金标是**第 184 条**（紧急救助免责）和**第 897 条**。

```
IDCG@10 = 1/log2(1+1) + 1/log2(2+1) = 1 + 0.6309 = 1.6309    两个金标都排最前时的 DCG

Dense：第 184 条排第 5 名，第 897 条不在前 10 名
DCG@10  = 1/log2(5+1) = 0.3869
NDCG@10 = 0.3869 / 1.6309 = 0.2372

重排后：第 184 条升到第 2 名
DCG@10  = 1/log2(2+1) = 0.6309
NDCG@10 = 0.6309 / 1.6309 = 0.3869
```

注意第 184 条是**怎么**被推上去的：种子第 1253 条（建筑物、搁置物致害）有 6 条 `depends` 边，同时指向第 184、1188、1190、1191、1192、1224 条。这些边来自**谓词名称匹配**（规则里共用“损害”一类的谓词），不是真正的法律依赖。第 184 条只是恰好在其中；不相关的第 1188 条也得到了同样的加分。

这正是论文里“关系精度约 15%”的含义：被语义网加分的条文里，大约七分之一是金标。这也说明 `depends` 这类候选需要专家审核，或者做参数和极性检查之后才可靠。
